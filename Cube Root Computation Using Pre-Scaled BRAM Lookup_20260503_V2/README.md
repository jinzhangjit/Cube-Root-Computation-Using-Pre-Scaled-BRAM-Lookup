# Pre-Scaled BRAM Cube Root Reproducibility Package (Chip-Level Edition)

This package accompanies the manuscript *An Ultra-Low Resource FPGA Architecture
for Cube Root Computation Using Pre-Scaled BRAM Lookup*. It provides the HDL
source, testbench, MATLAB precision scripts, BRAM table generator, and the
actual simulation/synthesis reports used to verify the results.

> **Synthesis methodology in this release.** This package performs synthesis in
> the **standard Vivado project flow (chip-level / non-OOC)**, so that
> automatically inferred I/O buffers (IBUF/OBUF) and the associated I/O delays
> and IOB switching power are included in the reported timing and power
> figures. This faithfully reproduces the chip-level numbers reported in the
> paper (F_max = 87.9 MHz, Dynamic Power = 24 mW).

## How to Reproduce

### 1. Vivado Functional Simulation

```bash
vivado -mode batch -source scripts/run_vivado_sim.tcl
```

Expected summary:

```text
Total tests   : 490
Passed        : 490
Failed        : 0
Max rel error : 0.1300% (paper: 0.13%)
Latency       : 3 cycles (paper: 3)
>>> ALL TESTS PASSED <<<
```

### 2. Vivado Synthesis and Implementation (chip-level / non-OOC)

```bash
vivado -mode batch -source scripts/synth_vivado.tcl
```

Reports are written to `build/synth_output/`. The reference reports from the
reproduced run are already included under `results/synthesis/`.

After completion, expect:

```text
Mode: chip-level (non-OOC), I/O buffers included
WNS  : -1.371 ns (timing closes at ~88 MHz, not 100 MHz target)
F_max: ~87.9 MHz
Dynamic Power: ~24 mW
LUT/FF/BRAM: 7 / 36 / 0.5 (1 RAMB18E1)
Bonded IOB  : 38 (auto-inferred IBUF/OBUF on every top-level port)
```

The negative WNS is **expected and correct**: at chip-level, the OBUF on the
output port adds ~3.8 ns of buffer delay, which combined with the 2.0 ns
output-delay budget overflows the 10 ns period. This determines the reported
F_max of ~88 MHz. If the core is instantiated as a sub-module of a larger
design (no top-level OBUF), F_max increases substantially (~290+ MHz). To
explore that scenario, replace the synthesis line in `scripts/synth_vivado.tcl`
with:

```tcl
synth_design -top $top_module -part $part -mode out_of_context
```

### 3. MATLAB Precision Analysis

From the package root:

```bash
matlab -batch "cd('matlab'); precision_analysis"
```

The reproduced run generated:

- `results/matlab/matlab_precision_analysis.log`
- `results/matlab/fig4_rel_error.png`
- `results/matlab/fig5_error_pdf.png`

### 4. Exhaustive Q2.22 Verification

```bash
python scripts/exhaustive_q2_22_precision.py
```

This checks all valid fixed-point inputs in the domain `[0.5, 4)`, from
`0x200000` to `0xFFFFFF`.

## Important Implementation Note

The BRAM read data register is intentionally coded without asynchronous reset:

```verilog
always @(posedge clk) begin
    bram_dout_s2 <= bram[bram_addr_s1];
end
```

This coding style is required for Vivado 2018.3 to infer `RAMB18E1`. Adding an
asynchronous reset to the BRAM data register can cause Vivado to implement the
table as LUT ROM instead of Block RAM.
